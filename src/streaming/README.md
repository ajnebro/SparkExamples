# Streaming examples

Examples based on Spark Structured Streaming. They must be run from the project root (see the
[main README](../../README.md)).

| Example | What it shows | What to observe |
| ------- | ------------- | --------------- |
| [temperature_sensor_generator.py](temperature_sensor_generator.py) | Not a Spark program: it simulates a sensor that writes a random temperature in a new file of `output/streaming` every 5 seconds. It is the data source of the streaming examples; run it in a separate terminal and stop it with Ctrl+C. | Each file is written to a hidden temporary file and then renamed, so Spark never reads a partially written file. |
| [fetch_file_by_interval.py](fetch_file_by_interval.py) | Not a Spark program: it downloads a URL (e.g. a CSV that a web site updates periodically) every few seconds, each time into a new file of a directory. It is a data source for streaming examples and, unlike the others, it takes command-line arguments: `python -m streaming.fetch_file_by_interval <url> <directory> <seconds> [--downloads N]`. Stop it with Ctrl+C. | Like the sensor generator, each file is written to a hidden temporary file and then renamed, so Spark never reads a partially downloaded file. |
| [temperature_sensor_with_timestamp_generator.py](temperature_sensor_with_timestamp_generator.py) | Not a Spark program: a variant of the sensor generator that identifies the sensor and adds a time stamp. Every few seconds it writes a file with the line `<sensor>,<temperature>,<time stamp>`. It takes command-line arguments: `python -m streaming.temperature_sensor_with_timestamp_generator <directory> <sensor> [--seconds S] [--readings N]`. Run several instances with different sensor names to simulate several sensors; stop them with Ctrl+C. | The files are CSV without header, ready to be read with `readStream` and an explicit schema. They are written atomically, like those of the other generator. |
| [streaming_average_temperature.py](streaming_average_temperature.py) | Read the directory of the sensor as a stream (`readStream`), compute the average temperature with `avg` and print it on the console after each micro-batch. Run the generator first, in another terminal. | An aggregation without a window needs the `complete` output mode, and the average covers all the files received since the query started, including the ones already in the directory (`make clean` removes them). |
| [streaming_find_high_temperature.py](streaming_find_high_temperature.py) | Read the directory of the sensor as a stream, keep only the temperatures higher than a threshold (`where`) and print them on the console. Run the generator first, in another terminal. | The values are text, so they must be cast to `double` before comparing; a query without aggregation uses the `append` mode, which writes each row once. |
| [streaming_average_temperature_from_several_sensors.py](streaming_average_temperature_from_several_sensors.py) | Read as a stream the CSV files of several sensors (`<sensor>,<temperature>,<time stamp>`, written by `temperature_sensor_with_timestamp_generator.py`) with an explicit schema, and compute the average and maximum temperature of each sensor with `groupBy`. Run one or more generators first, in other terminals. | A streaming source needs its schema to be given. With the `update` mode only the sensors whose statistics have changed in the micro-batch are printed. The time stamp column of the files is not used, so it is left out of the schema and Spark ignores it. |
| [streaming_average_temperature_with_time_windows.py](streaming_average_temperature_with_time_windows.py) | Group the temperatures of several sensors (CSV files written by `temperature_sensor_with_timestamp_generator.py`) in sliding time windows of 20 seconds every 10 seconds, with `window`, and compute the average of each sensor in each window. Run one or more generators first, in other terminals. | The windows use the time stamp written in the data (event time), not the time of arrival. As they overlap, each temperature appears in two windows. Sorting a streaming aggregation requires the `complete` mode, so the whole result is printed after every micro-batch. |
| [streaming_word_count_from_files.py](streaming_word_count_from_files.py) | Read the text files of a directory as a stream and count how many times each word appears, normalizing the text (lower case, split by anything that is not a letter or a digit) and sorting by frequency. There is no generator: copy text files (e.g. `cp data/quijote.txt output/streaming/`) while it runs. | The counts cover all the files received since the query started. Sorting needs the `complete` mode. A `groupBy` shuffles the data in `spark.sql.shuffle.partitions` partitions, 200 by default: the example sets 4, because 200 tasks per micro-batch are far too many for so little data (see the docstring of the module for the details). |
